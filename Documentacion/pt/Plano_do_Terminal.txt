CONTEXTO
====================================================================

O Bruno quer uma terminal própria, parecida com o Warp mas mais leve e rápida, com funções para trabalhar com agentes de IA:
 - várias abas/janelas com barra horizontal ou vertical
 - nomes de aba que resumem o que se faz nela e que rolam (marquee) se forem longos
 - um painel de agentes que abre uma aba e inicia o agente com um clique
 - um widget de uso por assinatura (Claude, Codex, Gemini…), com liga/desliga em Configurações
 - temas, fundo, fonte e tamanho configuráveis
 - um painel de servidores/portas com botão parar/iniciar
 - um painel de projetos com árvore de pastas
 - controle de alterações com git (local e remoto)
 - um widget de CPU/RAM em tempo real

Não há código prévio: é um projeto novo.

Decisões já tomadas com o usuário:
 - Stack Tauri 2 + Rust.
 - Resumo de aba híbrido: título OSC do agente, se não heurísticas, e LLM opcional.

Chaves de desempenho (o "mais rápido que o Warp"):
 - Saída da PTY. O Rust lê a ConPTY em uma thread dedicada. Agrupa a saída a cada ~4 ms ou 64 KB e a envia
   por um tauri::ipc::Channel binário, sem JSON por chunk, para term.write(Uint8Array). Haverá contrapressão
   (backpressure) se o xterm ficar para trás.
 - Renderização. xterm.js com o addon WebGL, com fallback para canvas. As abas ocultas não renderizam: continuam
   recebendo dados no buffer, mas sem pintar.
 - Frontend. SolidJS, sem VDOM e com um bundle de uns 30 KB. Painéis com lazy-load, então Git e a árvore
   não são carregados até serem abertos.
 - Backend. Os pollers (sys, usage, portas) rodam em tokio com intervalos configuráveis e são pausados se
   a janela estiver minimizada.
 - Metas mensuráveis:
   - inicialização a frio < 500 ms
   - RAM < 120 MB com 1 aba
   - latência de tecla < 10 ms
   - type de um arquivo de 100 MB em tempo comparável ao Windows Terminal
   São medidas na fase 9.

Rede corporativa:
 - reqwest com native-tls ou rustls-platform-verifier, para respeitar os certificados do sistema.
 - Proxy tomado de HTTPS_PROXY ou da config.

====================================================================
FUNCIONALIDADES (DESIGN)
====================================================================

1. Terminal real.
   - Perfis: PowerShell 7, Windows PowerShell, cmd, Git Bash, WSL e um custom.
   - ConPTY completa: cores de 24 bits, mouse, alt-screen, resize, Ctrl+C. Com isso funcionam vim, ssh
     e as TUIs de claude/codex/gemini.
   - Shell integration com scripts injetados para PowerShell, cmd (via clink opcional) e bash, que emitem
     OSC 133 (prompt, comando, exit code) e OSC 7 (cwd).
   - Isso habilita blocos no estilo Warp: navegar entre comandos, copiar a saída de um comando e marcar o
     exit code.

2. Layout.
   - Abas e splits (horizontal/vertical) dentro de cada aba.
   - Várias janelas do sistema (WebviewWindow).
   - Barra de abas em cima ou à esquerda (setting).
   - Atalhos: nova aba/janela, split, mover o foco e renomear.

3. Nome-resumo de aba (híbrido).
   - Ordem de prioridade:
     i.   Título fixado à mão.
     ii.  Título OSC 0/2 que o agente emite (o Claude Code coloca o resumo da tarefa).
     iii. Heurística: processo em foreground + último comando (OSC 133) + pasta do cwd + branch do git,
          por exemplo "claude · Proyecto-Demo (main)" ou "npm run dev · frontend".
     iv.  LLM opcional: endpoint compatível com OpenAI configurável (Ollama / vLLM da Spark). Resume as
          últimas N linhas a cada >=30 s e só se houve atividade.
   - Marquee: animação CSS se o texto transbordar. Pausa no hover e respeita prefers-reduced-motion.
     O tooltip mostra o texto completo.

4. Painel de Agentes.
   - Catálogo editável: Claude Code, Codex, Gemini CLI, OpenCode e custom (comando, args, env, ícone).
   - Detecção dos instalados com where, resolvendo os .cmd.
   - Um clique pede a pasta (ou usa o projeto ativo), abre uma aba nova e inicia o agente.
   - Dá para iniciar vários ao mesmo tempo e o painel mostra o estado de cada um
     (ativo / aguardando input / terminou).

5. Rodapé de uso (cada provedor é ativado ou desativado em Configurações).
   - Claude:
     - Fonte: o endpoint OAuth de uso que o /usage usa, com o token de ~/.claude/.credentials.json
       -> % da janela de 5 h e % semanal, com a hora do reset.
     - Fallback: somar tokens de ~/.claude/projects/**/*.jsonl.
   - Codex: lê-se o último evento rate_limits (primary/secondary used_percent e reset) de
     ~/.codex/sessions/**/rollout-*.jsonl.
   - Gemini CLI: não tem endpoint público de cota, então contam-se as requests locais (logs de
     ~/.gemini) contra um limite diário configurável. É marcado como "estimado".
   - Risco: essas fontes não são documentadas oficialmente. São verificadas na fase 5 e a UI mostra
     a fonte e se o dado é exato ou estimado.

6. Configurações (janela própria).
   - Aparência:
     - temas predefinidos + editor de cores + importar tema
     - fundo: cor, imagem, opacidade e efeito Mica/Acrylic (crate window-vibrancy)
     - fonte (lista de monoespaçadas do sistema + custom), tamanho, entrelinha, cursor e ligaduras
   - Interface e comportamento:
     - tema da UI do sistema (claro / escuro / auto)
     - posição da barra de abas
     - provedores de uso liga/desliga
     - agentes, shell padrão, atalhos, endpoint do LLM e frequência de polling
   - As mudanças são aplicadas ao vivo.

7. Painel de Servidores/Portas.
   - Lista as portas TCP em LISTEN com GetExtendedTcpTable -> PID -> nome, cmdline, cwd e uptime.
   - Destaca as que nasceram de abas do NovaTerm (descendentes das nossas PTY).
   - Parar: mata a árvore de processos. Pede confirmação se o processo não foi iniciado pelo app.
   - Iniciar: o app guarda uma "receita" (comando + cwd + env) de cada servidor que viu nascer em uma
     aba. Também é possível definir servidores à mão (tipo Procfile), que são iniciados em uma aba
     de fundo.
   - Limite honesto: um processo externo cujo comando não conhecemos não pode ser "iniciado"; só
     pode ser parado.

8. Painel de Projetos.
   - Projetos = cwds usados pelas abas de agentes, mais os descobertos em ~/.claude/projects
     (nomes de pasta que codificam o caminho) e no cwd das sessões do Codex, mais os adicionados
     à mão.
   - Árvore de pastas com carga lazy que respeita .gitignore (crate ignore) e é atualizada com notify.
   - Ações: abrir terminal ali, iniciar um agente ali, abrir no Explorer ou no VS Code, ver no Git.

9. Git (por projeto, com o git CLI para respeitar o Credential Manager e o proxy).
   - Estado local: status (--porcelain=v2), diff com visualização lado a lado ou unificada, stage/unstage por
     arquivo, commit.
   - Histórico e branches: log com grafo simples, criar/trocar branches.
   - Remoto: fetch/pull/push, clonar de uma URL remota, init.
   - Contador de alterações na aba ou projeto.

10. Widget superior de CPU/RAM.
    - CPU total e RAM usada/total, com sparkline de 60 s, a cada 1 s (sysinfo).
    - Ao clicar, mostra o top de processos e o consumo dos processos de cada aba.

ADENDO 17/11/2026 — AMBIENTE DE CASA (C:\Users\Br1)
====================================================================

O plano foi montado no PC do trabalho. A implementação começa no PC de casa, onde o ambiente é
diferente. O que foi verificado aqui:

 - Rust 1.99.1 (toolchain stable-x86_64-pc-windows-msvc) já instalado em ~/.cargo, mas fora do
   PATH: cada comando antepõe ~/.cargo/bin. Não é preciso instalar o rustup.
 - Node 22.22.2 e npm 11.14.1 (não Node 24). Git 2.56. Python 3.11 com fpdf2 2.8.7 (3.14 sem fpdf2).
 - VS 2022 + VS 2019 (linker MSVC) e WebView2 157 instalados.
 - Rede sem inspeção SSL nem proxy: crates.io, static.crates.io e npm respondem em < 0,3 s.
   Não é preciso ~/.cargo/config.toml nem --use-system-ca. Mesmo assim mantém-se o TLS do sistema
   (native-tls / schannel) para que o app funcione também na rede do trabalho.
 - Shells: Windows PowerShell 5.1, cmd, Git Bash e WSL. O PowerShell 5.1 é o perfil padrão e
   basta para todo o plano. O PowerShell 7 (pwsh) não está instalado: seu perfil fica no catálogo
   marcado "não detectado". O script de shell integration precisa ser compatível com a 5.1: usar
   [char]27 em vez de `e (que só existe a partir do PowerShell 6) e forçar a saída em UTF-8.
 - Agentes: claude (~/.local/bin/claude.exe), codex e opencode (shims .cmd do npm) e agy.
 - Dados para o rodapé de uso: existem ~/.claude/.credentials.json e ~/.codex/sessions.

O Gemini CLI passa a ser o Antigravity CLI (agy):
 - O Google substituiu o Gemini CLI pelo Antigravity CLI. O comando é "agy" (1.4.12 instalado em
   %LOCALAPPDATA%\agy\bin\agy.exe; dados em ~/.gemini/antigravity-cli). No catálogo de agentes,
   "Gemini CLI" é substituído por "Antigravity (agy)".
 - Uso: o agy traz a cota de forma oficial. "agy -p /quota --output-format json" devolve os
   grupos de modelos (Gemini; Claude e GPT; Gemini Argon) com a fração restante da janela de
   5 h e da semanal, e a hora do reset. Não roda um turno do agente nem gasta cota
   (num_turns 0, total_tokens 0). Verificado em 17/11/2026.
 - Com isso o provider deixa de ser "estimado": passa a ser um dado exato, melhor do que o plano
   previa para o Gemini. O provider o executa como processo direto (sem shell), a cada poucos minutos.
 - Cuidado: pelo Git Bash, "/quota" é convertido em um caminho do Windows (C:/Program Files/Git/quota)
   e o agy o toma como um prompt comum, que gasta cota. Executá-lo sem shell, ou pelo PowerShell
   ou cmd.

Ajustes de versões em relação ao plano (verificados no npm em 17/11/2026):
 - SolidJS 1.9.x e não 2.0: o vite-plugin-solid 2.11 só declara compatibilidade com solid-js ^1.7.2.
 - xterm.js 6.0 (@xterm/xterm) e não 5: o addon canvas (0.7) só suporta o xterm 5, então o
   fallback do WebGL passa a ser o renderer DOM que o xterm traz.
 - Vite 8.3, TypeScript 7.0, Vitest 5.1, Tauri 2.12 (CLI e API); são fixadas exatas na F1.
 - O reqwest 0.13 renomeou os features: usa-se native-tls + system-proxy.

O fallback para o Electron fica descartado enquanto o cargo funcionar (veja o Relatório).
