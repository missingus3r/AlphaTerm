Bruno quiere una terminal propia, parecida a Warp pero más liviana y rápida, con funciones de trabajo con agentes de IA:
 - pestañas/ventanas múltiples con barra horizontal o vertical
 - nombres de pestaña que resumen lo que se hace en ella y que se desplazan (marquee) si son largos
 - un panel de agentes que abre una pestaña y lanza el agente con un click
 - un widget de consumo por suscripción (Claude, Codex, Gemini…), con on/off en Settings
 - temas, fondo, fuente y tamaño configurables
 - un panel de servidores/puertos con botón detener/iniciar
 - un panel de proyectos con árbol de carpetas

 - un widget de CPU/RAM en tiempo real

ARQUITECTURA
====================================================================

Desktop\NovaTerm\
  src-tauri\        (Rust: backend)
    src\pty\        sesiones ConPTY (portable-pty), batching de salida, shell integration
    src\sys\        CPU/RAM (sysinfo), puertos/procesos (GetExtendedTcpTable via crate windows)
    src\git\        wrapper del git CLI (porcelain v2), parsers
    src\usage\      trait UsageProvider + claude.rs / codex.rs / gemini.rs
    src\projects\   descubrimiento de proyectos + árbol (crate ignore + notify)
    src\agents\     catálogo/detección de agentes (where.exe, shims .cmd)
    src\settings\   JSON en %APPDATA%\NovaTerm\settings.json
  src\              (frontend: Vite + TypeScript + SolidJS)
    terminal\       xterm.js 5 + addons webgl/fit/search/web-links/unicode11
    layout\         tabs, splits, barra H/V, marquee
    panels\         Agents, Servers, Projects, Git, Settings
    widgets\        TopBar (CPU/RAM), Footer (usage)
  Documentacion\    Especificación.pdf, Plan.pdf, Informe_Proceso_y_Stats.md, Guía de código.pdf

Claves de rendimiento (el "más rápido que Warp"):
 - Salida del PTY. Rust lee la ConPTY en un hilo dedicado. Agrupa la salida cada ~4 ms o 64 KB y la manda
   por un tauri::ipc::Channel binario, sin JSON por chunk, a term.write(Uint8Array). Habrá contrapresión
   (backpressure) si xterm se atrasa.
 - Render. xterm.js con el addon WebGL, con fallback a canvas. Las pestañas ocultas no renderizan: siguen
   recibiendo datos en el buffer, pero sin pintar.
 - Frontend. SolidJS, sin VDOM y con un bundle de unos 30 KB. Paneles con lazy-load, así que no se cargan
   Git ni el árbol hasta abrirlos.
 - Backend. Los pollers (sys, usage, puertos) corren en tokio con intervalos configurables y se pausan si
   la ventana está minimizada.
 - Metas medibles:
   - arranque en frío < 500 ms
   - RAM < 120 MB con 1 pestaña
   - latencia de tecla < 10 ms
   - type de un archivo de 100 MB en tiempo comparable a Windows Terminal
   Se miden en la fase 9.

Red corporativa:
 - reqwest con native-tls o rustls-platform-verifier, para respetar los certificados del sistema.
 - Proxy tomado de HTTPS_PROXY o de la config.

====================================================================
FUNCIONALIDADES (DISEÑO)
====================================================================

1. Terminal real.
   - Perfiles: PowerShell 7, Windows PowerShell, cmd, Git Bash, WSL y uno custom.
   - ConPTY completa: colores de 24 bits, mouse, alt-screen, resize, Ctrl+C. Con esto funcionan vim, ssh
     y los TUIs de claude/codex/gemini.
   - Shell integration con scripts inyectados para PowerShell, cmd (vía clink opcional) y bash, que emiten
     OSC 133 (prompt, comando, exit code) y OSC 7 (cwd).
   - Eso habilita bloques estilo Warp: navegar entre comandos, copiar la salida de un comando y marcar el
     exit code.

2. Layout.
   - Pestañas y splits (horizontal/vertical) dentro de cada pestaña.
   - Múltiples ventanas del sistema (WebviewWindow).
   - Barra de pestañas arriba o a la izquierda (setting).
   - Atajos: nueva pestaña/ventana, split, mover foco y renombrar.

3. Nombre-resumen de pestaña (híbrido).
   - Orden de prioridad:
     i.   Título fijado a mano.
     ii.  Título OSC 0/2 que emite el agente (Claude Code pone el resumen de la tarea).
     iii. Heurística: proceso en foreground + último comando (OSC 133) + carpeta del cwd + rama git,
          por ejemplo "claude · Proyecto-Demo (main)" o "npm run dev · frontend".
     iv.  LLM opcional: endpoint OpenAI-compatible configurable (Ollama / vLLM de la Spark). Resume las
          últimas N líneas cada >=30 s y solo si hubo actividad.
   - Marquee: animación CSS si el texto desborda. Se pausa en hover y respeta prefers-reduced-motion.
     El tooltip muestra el texto completo.

4. Panel de Agentes.
   - Catálogo editable: Claude Code, Codex, Gemini CLI, OpenCode y custom (comando, args, env, ícono).
   - Detección de instalados con where, resolviendo los .cmd.
   - Un click pide la carpeta (o usa el proyecto activo), abre una pestaña nueva y lanza el agente.
   - Se pueden lanzar varios a la vez y el panel muestra el estado de cada uno
     (activo / esperando input / terminó).

5. Footer de consumo (cada proveedor se activa o desactiva en Settings).
   - Claude:
     - Fuente: el endpoint OAuth de uso que usa /usage, con el token de ~/.claude/.credentials.json
       -> % de la ventana de 5 h y % semanal, con hora de reset.
     - Fallback: sumar tokens de ~/.claude/projects/**/*.jsonl.
   - Codex: se lee el último evento rate_limits (primary/secondary used_percent y reset) de
     ~/.codex/sessions/**/rollout-*.jsonl.
   - Gemini CLI: no tiene endpoint público de cuota, así que se cuentan las requests locales (logs de
     ~/.gemini) contra un límite diario configurable. Se marca como "estimado".
   - Riesgo: estas fuentes no están documentadas oficialmente. Se verifican en la fase 5 y la UI muestra
     la fuente y si el dato es exacto o estimado.

6. Settings (ventana propia).
   - Apariencia:
     - temas predefinidos + editor de colores + importar tema
     - fondo: color, imagen, opacidad y efecto Mica/Acrylic (crate window-vibrancy)
     - fuente (lista de monoespaciadas del sistema + custom), tamaño, interlineado, cursor y ligaduras
   - Interfaz y comportamiento:
     - tema de la UI del sistema (claro / oscuro / auto)
     - posición de la barra de pestañas
     - proveedores de consumo on/off
     - agentes, shell por defecto, atajos, endpoint del LLM y frecuencia de polling
   - Los cambios se aplican en vivo.

7. Panel de Servidores/Puertos.
   - Lista los puertos TCP en LISTEN con GetExtendedTcpTable -> PID -> nombre, cmdline, cwd y uptime.
   - Resalta los que nacieron de pestañas de NovaTerm (descendientes de nuestros PTY).
   - Detener: mata el árbol de procesos. Pide confirmación si el proceso no fue lanzado por la app.
   - Iniciar: la app guarda una "receta" (comando + cwd + env) de cada servidor que vio nacer en una
     pestaña. También se pueden definir servidores a mano (tipo Procfile), que se arrancan en una pestaña
     de fondo.
   - Límite honesto: un proceso externo del que no conocemos el comando no se puede "iniciar"; solo se
     puede detener.

8. Panel de Proyectos.
   - Proyectos = cwds usados por las pestañas de agentes, más los descubiertos en ~/.claude/projects
     (nombres de carpeta que codifican la ruta) y en el cwd de las sesiones de Codex, más los agregados
     a mano.
   - Árbol de carpetas con carga lazy que respeta .gitignore (crate ignore) y se actualiza con notify.
   - Acciones: abrir terminal ahí, lanzar un agente ahí, abrir en Explorer o VS Code, ver en Git.

9. Git (por proyecto, con el git CLI para respetar el Credential Manager y el proxy).
   - Estado local: status (--porcelain=v2), diff con vista lado a lado o unificada, stage/unstage por
     archivo, commit.
   - Historial y ramas: log con grafo simple, crear/cambiar ramas.
   - Remoto: fetch/pull/push, clonar desde URL remota, init.
   - Contador de cambios en la pestaña o proyecto.

10. Widget superior de CPU/RAM.
    - CPU total y RAM usada/total, con sparkline de 60 s, cada 1 s (sysinfo).
    - Al hacer click, muestra el top de procesos y el consumo de los procesos de cada pestaña.

El plan se armó en la PC del trabajo. La implementación arranca en la PC de casa, donde el entorno es
distinto. Lo verificado acá:

 - Rust 1.99.1 (toolchain stable-x86_64-pc-windows-msvc) ya instalado en ~/.cargo, pero fuera del
   PATH: cada comando antepone ~/.cargo/bin. No hace falta instalar rustup.
 - Node 22.22.2 y npm 11.14.1 (no Node 24). Git 2.56. Python 3.11 con fpdf2 2.8.7 (3.14 sin fpdf2).
 - VS 2022 + VS 2019 (linker MSVC) y WebView2 157 instalados.
 - Red sin inspección SSL ni proxy: crates.io, static.crates.io y npm responden en < 0,3 s.
   No hace falta ~/.cargo/config.toml ni --use-system-ca. Igual se mantiene TLS del sistema
   (native-tls / schannel) para que la app ande también en la red del trabajo.
 - Shells: Windows PowerShell 5.1, cmd, Git Bash y WSL. PowerShell 5.1 es el perfil por defecto y
   alcanza para todo el plan. PowerShell 7 (pwsh) no está instalado: su perfil queda en el catálogo
   marcado "no detectado". El script de shell integration tiene que ser compatible con 5.1: usar
   [char]27 en vez de `e (que recién existe en PowerShell 6) y forzar la salida en UTF-8.
 - Agentes: claude (~/.local/bin/claude.exe), codex y opencode (shims .cmd de npm) y agy.
 - Datos para el footer de consumo: existen ~/.claude/.credentials.json y ~/.codex/sessions.

Gemini CLI pasa a ser Antigravity CLI (agy):
 - Google reemplazó Gemini CLI por Antigravity CLI. El comando es "agy" (1.4.12 instalado en
   %LOCALAPPDATA%\agy\bin\agy.exe; datos en ~/.gemini/antigravity-cli). En el catálogo de agentes,
   "Gemini CLI" se reemplaza por "Antigravity (agy)".
 - Consumo: agy trae la cuota de forma oficial. "agy -p /quota --output-format json" devuelve los
   grupos de modelos (Gemini; Claude y GPT; Gemini Argon) con la fracción restante de la ventana de
   5 h y de la semanal, y la hora de reset. No corre un turno del agente ni gasta cuota
   (num_turns 0, total_tokens 0). Verificado el 17/11/2026.
 - Con esto el provider deja de ser "estimado": pasa a ser un dato exacto, mejor que lo que el plan
   preveía para Gemini. El provider lo ejecuta como proceso directo (sin shell), cada pocos minutos.
 - Cuidado: desde Git Bash, "/quota" se convierte en una ruta de Windows (C:/Program Files/Git/quota)
   y agy lo toma como un prompt común, que sí gasta cuota. Ejecutarlo sin shell, o desde PowerShell
   o cmd.

Ajustes de versiones respecto del plan (verificados en npm el 17/11/2026):
 - SolidJS 1.9.x y no 2.0: vite-plugin-solid 2.11 solo declara compatibilidad con solid-js ^1.7.2.
 - xterm.js 6.0 (@xterm/xterm) y no 5: el addon canvas (0.7) solo soporta xterm 5, así que el
   fallback del WebGL pasa a ser el renderer DOM que trae xterm.
 - Vite 8.3, TypeScript 7.0, Vitest 5.1, Tauri 2.12 (CLI y API); se fijan exactas en F1.
 - reqwest 0.13 renombró los features: se usa native-tls + system-proxy.

El fallback a Electron queda descartado mientras cargo funcione (ver Informe).
