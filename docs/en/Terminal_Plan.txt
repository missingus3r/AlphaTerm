====================================================================
CONTEXT
====================================================================

Bruno wants a terminal of his own, similar to Warp but lighter and faster, with features for working with AI agents:
 - multiple tabs/windows with a horizontal or vertical bar
 - tab names that summarize what is being done in them and scroll (marquee) when they are long
 - an Agents panel that opens a tab and launches the agent with one click
 - a per-subscription usage widget (Claude, Codex, Gemini…), with on/off in Settings
 - configurable themes, background, font and size
 - a Servers/ports panel with a stop/start button
 - a Projects panel with a folder tree
 - change control with git (local and remote)
 - a real-time CPU/RAM widget

There is no prior code: it is a new project.

Decisions already made with the user:
 - Tauri 2 + Rust stack.
 - Hybrid tab summary: the agent's OSC title, otherwise heuristics, and an optional LLM.

Detected environment:
 - Node 24, Git 2.53, Python 3.14, VS 2022 (for the MSVC linker) and WebView2 157 are installed.
 - Rust is not installed.
 - static.rust-lang.org and npm do respond.
 - objects.githubusercontent.com is blocked.
 - crates.io did not respond within 10 s; it needs to be checked.
 - The corporate network does SSL inspection: Node needed --use-system-ca.
 - PowerShell blocks .ps1, so .cmd has to be used.

ARCHITECTURE
====================================================================

Desktop\NovaTerm\   (since 18/11/2026: Desktop\AlphaTerm\)
  src-tauri\        (Rust: backend)
    src\pty\        ConPTY sessions (portable-pty), output batching, shell integration
    src\sys\        CPU/RAM (sysinfo), ports/processes (GetExtendedTcpTable via the windows crate)
    src\git\        git CLI wrapper (porcelain v2), parsers
    src\usage\      UsageProvider trait + claude.rs / codex.rs / gemini.rs
    src\projects\   project discovery + tree (ignore crate + notify)
    src\agents\     agent catalog/detection (where.exe, .cmd shims)
    src\settings\   JSON in %APPDATA%\NovaTerm\settings.json
  src\              (frontend: Vite + TypeScript + SolidJS)
    terminal\       xterm.js 5 + webgl/fit/search/web-links/unicode11 addons
    layout\         tabs, splits, H/V bar, marquee
    panels\         Agents, Servers, Projects, Git, Settings
    widgets\        TopBar (CPU/RAM), Footer (usage)
  docs\    Specification.pdf, Plan.pdf, Process_Report.md, Code_Guide.pdf

Performance keys (the "faster than Warp"):
 - PTY output. Rust reads the ConPTY on a dedicated thread. It batches the output every ~4 ms or 64 KB and sends it
   over a binary tauri::ipc::Channel, with no JSON per chunk, to term.write(Uint8Array). There will be backpressure
   if xterm falls behind.
 - Rendering. xterm.js with the WebGL addon, with a canvas fallback. Hidden tabs don't render: they keep
   receiving data in the buffer, but without painting.
 - Frontend. SolidJS, no VDOM and a bundle of about 30 KB. Lazy-loaded panels, so neither
   Git nor the tree is loaded until they are opened.
 - Backend. The pollers (sys, usage, ports) run in tokio with configurable intervals and pause if
   the window is minimized.
 - Measurable goals:
   - cold start < 500 ms
   - RAM < 120 MB with 1 tab
   - key latency < 10 ms
   - type of a 100 MB file in a time comparable to Windows Terminal
   They are measured in phase 9.

Corporate network:
 - reqwest with native-tls or rustls-platform-verifier, to respect the system certificates.
 - Proxy taken from HTTPS_PROXY or from the config.

====================================================================
FEATURES (DESIGN)
====================================================================

1. A real terminal.
   - Profiles: PowerShell 7, Windows PowerShell, cmd, Git Bash, WSL and a custom one.
   - Full ConPTY: 24-bit colors, mouse, alt-screen, resize, Ctrl+C. With this, vim, ssh
     and the claude/codex/gemini TUIs work.
   - Shell integration with injected scripts for PowerShell, cmd (via optional clink) and bash, which emit
     OSC 133 (prompt, command, exit code) and OSC 7 (cwd).
   - That enables Warp-style blocks: navigating between commands, copying a command's output and marking the
     exit code.

2. Layout.
   - Tabs and splits (horizontal/vertical) inside each tab.
   - Multiple system windows (WebviewWindow).
   - Tab bar on top or on the left (setting).
   - Shortcuts: new tab/window, split, move focus and rename.

3. Tab summary name (hybrid).
   - Priority order:
     i.   A title pinned by hand.
     ii.  OSC 0/2 title emitted by the agent (Claude Code puts the task summary).
     iii. Heuristic: foreground process + last command (OSC 133) + cwd folder + git branch,
          for example "claude · Proyecto-Demo (main)" or "npm run dev · frontend".
     iv.  Optional LLM: configurable OpenAI-compatible endpoint (Ollama / vLLM on the Spark). It summarizes the
          last N lines every >=30 s and only if there was activity.
   - Marquee: CSS animation if the text overflows. It pauses on hover and respects prefers-reduced-motion.
     The tooltip shows the full text.

4. Agents panel.
   - Editable catalog: Claude Code, Codex, Gemini CLI, OpenCode and custom (command, args, env, icon).
   - Detection of installed ones with where, resolving the .cmd files.
   - One click asks for the folder (or uses the active project), opens a new tab and launches the agent.
   - Several can be launched at once and the panel shows each one's status
     (active / waiting for input / finished).

5. Usage footer (each provider is turned on or off in Settings).
   - Claude:
     - Source: the OAuth usage endpoint that /usage uses, with the token from ~/.claude/.credentials.json
       -> % of the 5 h window and weekly %, with reset time.
     - Fallback: add up tokens from ~/.claude/projects/**/*.jsonl.
   - Codex: the latest rate_limits event is read (primary/secondary used_percent and reset) from
     ~/.codex/sessions/**/rollout-*.jsonl.
   - Gemini CLI: it has no public quota endpoint, so local requests are counted (logs from
     ~/.gemini) against a configurable daily limit. It is marked as "estimated".
   - Risk: these sources are not officially documented. They are verified in phase 5 and the UI shows
     the source and whether the figure is exact or estimated.

6. Settings (its own window).
   - Appearance:
     - preset themes + color editor + import theme
     - background: color, image, opacity and Mica/Acrylic effect (window-vibrancy crate)
     - font (list of the system's monospaced fonts + custom), size, line height, cursor and ligatures
   - Interface and behavior:
     - system UI theme (light / dark / auto)
     - tab bar position
     - usage providers on/off
     - agents, default shell, shortcuts, LLM endpoint and polling frequency
   - Changes are applied live.

7. Servers/Ports panel.
   - Lists the TCP ports in LISTEN with GetExtendedTcpTable -> PID -> name, cmdline, cwd and uptime.
   - Highlights the ones that were born from NovaTerm tabs (descendants of our PTYs).
   - Stop: kills the process tree. Asks for confirmation if the process was not launched by the app.
   - Start: the app saves a "recipe" (command + cwd + env) for each server it saw start in a
     tab. Servers can also be defined by hand (Procfile-style), and they are started in a background
     tab.
   - Honest limit: an external process whose command we don't know can't be "started"; it can only
     be stopped.

8. Projects panel.
   - Projects = cwds used by the agent tabs, plus the ones discovered in ~/.claude/projects
     (folder names that encode the path) and in the cwd of Codex sessions, plus the ones added
     by hand.
   - Lazy-loaded folder tree that respects .gitignore (ignore crate) and updates with notify.
   - Actions: open a terminal there, launch an agent there, open in Explorer or VS Code, view in Git.

9. Git (per project, with the git CLI to respect the Credential Manager and the proxy).
   - Local state: status (--porcelain=v2), diff in side-by-side or unified view, stage/unstage per
     file, commit.
   - History and branches: log with a simple graph, create/switch branches.
   - Remote: fetch/pull/push, clone from a remote URL, init.
   - Change counter on the tab or project.

10. Top CPU/RAM widget.
    - Total CPU and used/total RAM, with a 60 s sparkline, every 1 s (sysinfo).
    - On click, it shows the top processes and the usage of each tab's processes.

ADDENDUM 17/11/2026 — HOME ENVIRONMENT (C:\Users\Br1)
====================================================================

The plan was put together on the work PC. Implementation starts on the home PC, where the environment is
different. What was verified here:

 - Rust 1.99.1 (toolchain stable-x86_64-pc-windows-msvc) already installed in ~/.cargo, but outside the
   PATH: every command prepends ~/.cargo/bin. There is no need to install rustup.
 - Node 22.22.2 and npm 11.14.1 (not Node 24). Git 2.56. Python 3.11 with fpdf2 2.8.7 (3.14 without fpdf2).
 - VS 2022 + VS 2019 (MSVC linker) and WebView2 157 installed.
 - Network with no SSL inspection or proxy: crates.io, static.crates.io and npm respond in < 0.3 s.
   There is no need for ~/.cargo/config.toml or --use-system-ca. System TLS is still kept
   (native-tls / schannel) so the app also works on the work network.
 - Shells: Windows PowerShell 5.1, cmd, Git Bash and WSL. PowerShell 5.1 is the default profile and
   is enough for the whole plan. PowerShell 7 (pwsh) is not installed: its profile stays in the catalog
   marked "not detected". The shell integration script has to be compatible with 5.1: use
   [char]27 instead of `e (which only exists from PowerShell 6) and force UTF-8 output.
 - Agents: claude (~/.local/bin/claude.exe), codex and opencode (npm .cmd shims) and agy.
 - Data for the usage footer: ~/.claude/.credentials.json and ~/.codex/sessions exist.

Gemini CLI becomes Antigravity CLI (agy):
 - Google replaced Gemini CLI with Antigravity CLI. The command is "agy" (1.4.12 installed in
   %LOCALAPPDATA%\agy\bin\agy.exe; data in ~/.gemini/antigravity-cli). In the agent catalog,
   "Gemini CLI" is replaced by "Antigravity (agy)".
 - Usage: agy provides the quota officially. "agy -p /quota --output-format json" returns the model
   groups (Gemini; Claude and GPT; Gemini Argon) with the remaining fraction of the 5 h window and of the
   weekly one, and the reset time. It doesn't run an agent turn or spend quota
   (num_turns 0, total_tokens 0). Verified on 17/11/2026.
 - With this, the provider is no longer "estimated": it becomes an exact figure, better than what the plan
   expected for Gemini. The provider runs it as a direct process (no shell), every few minutes.
 - Careful: from Git Bash, "/quota" gets converted into a Windows path (C:/Program Files/Git/quota)
   and agy takes it as an ordinary prompt, which does spend quota. Run it without a shell, or from PowerShell
   or cmd.

Version adjustments relative to the plan (verified on npm on 17/11/2026):
 - SolidJS 1.9.x and not 2.0: vite-plugin-solid 2.11 only declares compatibility with solid-js ^1.7.2.
 - xterm.js 6.0 (@xterm/xterm) and not 5: the canvas addon (0.7) only supports xterm 5, so the
   WebGL fallback becomes the DOM renderer that xterm ships.
 - Vite 8.3, TypeScript 7.0, Vitest 5.1, Tauri 2.12 (CLI and API); they are pinned exactly in F1.
 - reqwest 0.13 renamed the features: native-tls + system-proxy is used.

The Electron fallback is dropped as long as cargo works (see Report).

ADDENDUM 18/11/2026 — ALPHATERM AND FEATURES REQUESTED DURING IMPLEMENTATION
====================================================================

Name change: the app is now called AlphaTerm (binary alphaterm.exe, identifier
uy.alphaterm.app, data in %APPDATA%\AlphaTerm; the first time, the NovaTerm folder is copied).
This txt keeps its original name as a record of the plan.

Features added at Bruno's request (besides F3 to F9):
 - History of all commands (all tabs and windows), searchable, reusable.
 - A widget with the current location (clickable segments, git branch).
 - The usage of the open agent always stays visible and highlighted in the footer, with detail.
 - On opening, the last state is recovered (windows, tabs, panels, folders, colors, title).
 - Paths in the output (from agents or anything else) become links: they open the folder or the file;
   on mouse hover they show a preview (image, text or folder contents).
 - Tab folders (collapsible, with color) and color per tab.
 - Window title pinned by hand.
 - Control API for agents (local HTTP with a token + MCP server + CLI): see tabs, open
   tabs, panes and sub-windows, run commands and read their output.
 - Docker panel: start configured containers with one click (templates), manage the
   existing ones, logs and shell; also from the API for agents.
 - Guardian: asks before an agent deletes or modifies files (turned off in
   Settings). It stops Claude Code (hooks) and Codex (its approval mode) launched from
   AlphaTerm, and whatever goes through the API. Honest limit: it can't stop any program
   (Windows doesn't allow it without a file system driver).

Deviations from the original plan:
 - Claude usage: the OAuth endpoint with the token from .credentials.json is not used (a decision already
   made in the Claude Control Panel: don't touch credentials). The exact figure comes from Claude Code's
   statusline; without it, it is estimated from the transcripts (no percentage).
 - Codex stores its sessions compressed (.jsonl.zst): they are read with ruzstd.
 - Gemini CLI → Antigravity (agy) with the official /quota (see the previous addendum).
